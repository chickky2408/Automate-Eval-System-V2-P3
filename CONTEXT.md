# Domain Context & Glossary

## Logging & Observability

### Job Execution Log
The chronological text output (stdout/stderr) generated during a test case or job run on the target hardware (KR260 / KV260 / Zybo). Contains execution timestamps, DMA driver register setup, hex instruction loading, and hardware error codes. Stored as raw `.log` flat files in `uploads/LOG/{year}/{month}/{result_id}.log`.

### System Event Log
A structured, indexed diagnostic record generated by the central management platform (FastAPI), BoardManager watchdog, JobQueueService, and background workers. Stores attributes: `timestamp`, `level` (INFO, WARN, ERROR), `source` (e.g., `board_manager`, `job_runner`, `dma_engine`), `board_id`, `job_id`, and `message`. Stored in the `system_logs` database table.

### Batch Log Flush
The transport strategy where the FPGA board agent accumulates all execution log records in memory during the test execution and transfers the complete log buffer to the central server in the final completion payload (`post_measurements`), avoiding network traffic during high-speed DMA streaming.

### System Log Retention & Cleanup
Policy where structured system events are retained for a configurable TTL (e.g., 30 days) with automated background pruning, complemented by administrative manual purging under the Library Cleanup utility (`/cleanup`).

### Live Log Broadcasting
The transmission of newly ingested system event logs from the FastAPI backend to the React dashboard over WebSocket (`/ws`), rendering newly arriving events dynamically without requiring manual page refresh.

## Waveform Verification & Expected Comparison

### Expected Waveform (Expected VCD)
The canonical, expected digital logic trace (Value Change Dump) provided as the simulation or specification baseline for a test case. Serves as the ground-truth reference against which physical FPGA hardware captures (Actual Waveform) are compared.

### Actual Waveform (Hardware Capture)
The physical logic signals acquired from the device under test (DUT) via the FPGA AXI DMA ring buffer, encoded as an LZ4-compressed stream (`.bin.lz4`) and converted to HDF5 (`.h5`) for verification against the Expected Waveform.

### Trigger Edge Alignment (Sync Offset)
The time-synchronization technique that establishes a common $t=0$ anchor between an Expected VCD and an Actual hardware capture by detecting the first active transition (rising/falling edge) on a designated synchronization channel (e.g., `CH0` or Start strobe), compensating for hardware trigger latency and execution start skews.

### Signal Mapping Specification
The configuration schema that associates named hierarchical simulation variables from an Expected VCD (e.g., `tb.dut.spi_mosi`, `clk`) to the corresponding physical captured channels on the FPGA capture hardware (`CH0` through `CH7`).

### Jitter Tolerance Window (Slack Window)
The acceptable temporal margin of error ($\pm N$ clock samples or $\pm \Delta t$ nanoseconds) within which an actual hardware signal transition is allowed to lead or lag the ideal Expected transition without triggering a logic mismatch, accommodating propagation delay and clock skew.

### Waveform Mismatch Marker
A discrete discrepancy record identifying a specific signal channel, expected logical state, actual captured state, time offset, and duration where the Actual hardware capture deviated from the Expected reference beyond the Jitter Tolerance Window.

### Hybrid Waveform Verification Engine
The architectural workflow combining server-side automated bit-level diff calculation (yielding pass/fail verdict and mismatch metadata during ingest) with client-side dual-trace visual overlay (Expected vs. Actual) in the Web Waveform Viewer for rapid interactive debugging.

### Layered Comparison Engine (Dual-Stage Diff)
The two-phase verification pipeline where Stage 1 executes high-speed vectorized Sample-Grid XOR screening across millions of samples in milliseconds, and Stage 2 selectively triggers deep event/strobe inspection only when Stage 1 detects a deviation.

### Verification Masking (Channel & Window Mask)
The selective filtering configuration permitting users to designate specific active channels (Channel Mask) and precise temporal bounds (Time-Window Mask $[t_{\text{start}}, t_{\text{end}}]$) for comparison, treating unmasked intervals and signals as Don't Care (X).

### Binary Mismatch Metric
The quantification of test deviation expressed as total mismatched sample count ($N_{\text{mismatch}}$) and the timestamp of the first observed discrepancy ($t_{\text{first\_mismatch}}$), providing an unambiguous, high-speed indicator of verification pass/fail status.

### Edge-Based F1 Matching Score
A normalized similarity percentage ($0.0\%$ to $100.0\%$) evaluating how accurately physical transition events (0→1 and 1→0 edges) in the Actual capture correspond to the Expected model:
- **True Positive (TP):** An expected edge successfully matched by an actual edge within the Jitter Tolerance Window.
- **False Positive (FP):** An extraneous actual edge (glitch or noise pulse) that has no corresponding expected transition.
- **False Negative (FN):** An expected transition that failed to occur in the actual capture (dropped pulse or stuck line).
Calculated via harmonic mean: $\text{F1} = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}} \times 100\%$, providing resilience against constant phase delays while strictly penalizing missing or extra glitches.

### Dual-Metric Verification Architecture
The production verification policy where **both** the Sample-Grid Bitwise XOR Match percentage (`sample_xor_score`) and the Edge-Based F1 Matching Score (`f1_score`) are computed concurrently and surfaced to users:
- **Sample-Grid XOR Match %:** Evaluates zero-tolerance bit equivalence sample-by-sample for strict digital simulation regression.
- **Edge-Based F1-Score:** Evaluates sequence and pulse integrity within the Jitter Tolerance Window, accommodating board propagation delays and phase shifts without false negative failures.
- **Status Classification:** `PASS` (100% bit match), `PASS_WITH_JITTER` (edge sequence intact with minor physical delay/glitches), `MARGINAL` (near threshold), and `FAIL` (functional breakdown).

### Clock-Synchronous Majority Voting XOR
A cycle-accurate verification filter that samples each clock period across 10 sub-cycle points ($P_0$ through $P_9$) between consecutive active edges, resolving the cycle's logical state by democratic majority vote ($> 50\%$ threshold):
- **Propagation Delay Absorption:** Absorbs bus skew up to 40% of the clock period, resolving intact signals to 100.0% match.
- **Glitch Immunity:** Suppresses transient noise spikes without generating false-positive verification alarms.
- **Vote Confidence Metric:** Measures average winning margin (`majority_avg_confidence`), providing an unambiguous indicator of signal eye margin.

### Ghost Line Waveform Overlay
The visualization pattern where the Expected Golden waveform is rendered as a semi-transparent dashed trace ("Ghost Line") directly on top of the solid Actual hardware capture track within the Web Waveform Viewer, allowing immediate visual detection of propagation delays, phase shifts, and bit errors without requiring vertical track duplication.

### Mismatch Highlight Band
A semi-transparent red bounding interval rendered dynamically across the canvas over temporal windows where the Actual hardware signal deviates from the Expected reference beyond the configured tolerance, providing immediate visual anchoring during debugging.

### Diff Stepper Navigation
An interactive navigation suite composed of toolbar jump buttons (`[◀ Prev Diff]`, `[Next Diff ▶]`) and an expandable Discrepancy Drawer table, enabling test engineers to cycle the viewer's viewport and cursors through all recorded mismatch zones in sequence.

### Verification Diff Artifact
A specialized off-database compressed diagnostic file (`.diff.json.lz4`) stored in the platform file store (`uploads/DIFF/{year}/{month}/{result_id}.diff.json.lz4`), retaining the complete, high-volume timestamp logs of all mismatched samples while preserving relational database query agility.

### Test Case Comparator Configuration
The schema encapsulated within `test_cases.config_options["comparator_config"]` specifying signal-to-channel mapping (e.g. `tb.dut.spi_mosi` $\leftrightarrow$ `CH3`), synchronization trigger channel, reference clock channel, verification mode (`DUAL`, `MAJORITY_XOR`, etc.), and tolerance parameters.

### Asynchronous Verification Task
The decoupled post-ingestion comparison job executed in the background after acknowledging the FPGA board upload with HTTP 200, updating database scores and broadcasting results over WebSocket (`/ws`) without holding the physical test board's HTTP connection.

### Unified Waveform Diff Payload
The aggregated JSON response model served by `GET /api/v1/results/{id}/waveform-diff` combining Actual channel traces, Expected ghost traces, metadata verification badges, and bounded mismatch intervals ready for immediate 60fps canvas rendering.
